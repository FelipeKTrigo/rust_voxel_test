1 Stack Tecnológico

🎮 Renderização & Janela
  • wgpu — API gráfica cross-platform (WebGPU), renderização 3D e compute shaders
  • winit — janela, eventos de input e loop de eventos
  • bytemuck — casting seguro para buffers GPU (vértices, uniforms)
🧮 Matemática & Ruído
  • glam — vetores e matrizes otimizados (Vec3, Mat4)
  • noise — Simplex/Perlin noise na CPU (seed, oitavas, persistência)
  • Shaders WGSL customizados para noise na GPU
🖥️ Interface (UI)
  • egui — UI imediata (menus, pausa, configurações)
  • egui-wgpu — integração egui com pipeline wgpu
  • Tela inicial, menu de pausa, criação de mundo
⚙️ Sistemas & Dados
  • rayon — paralelismo CPU (geração de mesh, chunks)
  • serde + bincode — serialização de chunks e saves
  • log + env_logger — logging estruturado
  • anyhow — tratamento de erros ergonômico
💡 Por que wgpu? wgpu é a escolha natural em Rust — suporta Vulkan, Metal, DX12 e WebGPU na mesma API, tem compute shaders (essencial para geração na GPU) e é a crate mais madura para gráficos em Rust.

Fluxo do Game Loop

// Ciclo principal a cada frame
loop {
    // 1. Processar eventos (input, resize, fechar)
    event_loop.handle_events(&input);

    // 2. Atualizar estado
    if !paused {
        player.update(dt, &input);
        physics.step(dt, &world);
        chunk_manager.update(&player.position);  // carregar/descarregar chunks
        world_gen.poll_gpu_results();             // pegar chunks prontos da GPU
    }

    // 3. Renderizar
    renderer.render(&world, &camera, &ui_state);
}

5 Geração de Mundo na GPU

Pipeline de Geração por Chunk

// Fluxo GPU para cada chunk novo
// 1. Dispatch compute shader com posição do chunk como uniform
ComputePass::dispatch(heightmap_shader, chunk_x, chunk_z);
ComputePass::dispatch(biome_shader, chunk_x, chunk_z);

// 2. Resultados vão para storage buffer na GPU
// 3. Readback assíncrono (não bloqueia o render thread)
queue.submit([encoder.finish()]);
buffer_slice.map_async(MapMode::Read, callback);

// 4. Callback popula o Chunk com blocos
for x in 0..32 {
    for z in 0..32 {
        let height = heightmap[x][z];  // vem da GPU
        let biome  = biome_map[x][z];   // vem da GPU
        chunk.populate_column(x, z, height, biome);
    }
}

Shader de Heightmap (WGSL)

// assets/shaders/compute/heightmap.wgsl
@group(0) @binding(0) var<storage, read_write> heightmap: array<f32>;
@group(0) @binding(1) var<uniform> params: ChunkParams;

@compute @workgroup_size(8, 8, 1)
fn main(@builtin(global_invocation_id) gid: vec3<u32>) {
    let world_x = f32(gid.x + params.chunk_x * 32u);
    let world_z = f32(gid.y + params.chunk_z * 32u);

    // Noise multi-oitava: continente + detalhe + montanhas
    var h = simplex(world_x * 0.003, world_z * 0.003) * 80.0;  // base
    h += simplex(world_x * 0.01,  world_z * 0.01)  * 25.0;  // colinas
    h += simplex(world_x * 0.05,  world_z * 0.05)  * 8.0;   // detalhe
    h += ridge_noise(world_x * 0.008, world_z * 0.008) * 60.0; // montanhas

    heightmap[gid.y * 32u + gid.x] = clamp(h + 64.0, 1.0, 255.0);
}

Árvores Cross-Chunk

🌲 Estratégia Determinística

Cada árvore tem uma posição calculada a partir do seed do mundo + coordenadas do chunk. Ao gerar o mesh de qualquer chunk, ele consulta os chunks vizinhos (via um "lookahead" de ±2 chunks) para incluir troncos e galhos que se estendem para além das bordas.

  • Função: tree_positions_in_chunk(world_seed, chunk_x, chunk_z) → Vec<(i32,i32)>
  • Sempre gera os mesmos pontos para o mesmo chunk
  • O mesh do chunk inclui blocos de árvores de chunks vizinhos se eles estiverem dentro dos bounds

Dunas onduladas. Muito quente, umidade mínima.

Oceano

Nível d'água ~63. Temperatura média, umidade máxima.

  • Barcos de pescadores de rede
  • Visibilidade reduzida abaixo da água
🗺️ Biome Blending via Temperatura × Umidade

Um ponto no espaço tem dois valores noise: temperatura (−1 a 1) e umidade (−1 a 1). O bioma resulta do quadrante no mapa 2D. Voronoi adiciona "centros" de bioma com bordas suaves (distância ponderada entre os 2 biomas mais próximos para blend de blocos nas fronteiras).

7 Sistema de Chunks

📦 Dimensões do Chunk
  • Tamanho: 32×32×256 blocos por chunk
  • 32 escolhido (vs 16) para melhor utilização do workgroup 8×8 da GPU
  • Altura 256: permite montanhas altas e ravinas profundas
  • Nível do mar: Y = 63
🔄 Estados de um Chunk
  • Unloaded — fora do alcance
  • Queued — aguardando geração na GPU
  • Generated — dados de bloco prontos
  • Meshed — mesh GPU pronta para render
  • Dirty — bloco modificado, precisa remesh
🎚️ LOD por Distância
  • 0–8 chunks: full resolution, greedy mesh completo
  • 8–16 chunks: merge de blocos similares em colunas
  • 16+ chunks: mesh ultralight (apenas topo das colunas)

10 Decisões Arquiteturais Chave

Greedy Meshing em vez de Naive Meshing

Naive cria um quad por face visível de bloco — até 6×N quads. Greedy agrupa faces adjacentes do mesmo tipo em retângulos maiores, reduzindo vértices em ~80–95% em áreas uniformes.

→ Essencial para performance com 32³ × 256 blocos por chunk

Voronoi para Biomas: Vale a pena?

Sim. Voronoi cria regiões orgânicas de bioma (como "células"), evitando as transições em faixas horizontais do noise puro. Combinado com suavização de distância entre os 2 biomas mais próximos, resulta em fronteiras naturais sem serem bruscas.

→ Implementar com GPU Voronoi no shader de bioma

Montanhas contínuas entre chunks

O shader de heightmap usa coordenadas de mundo globais (não locais ao chunk). Logo, o mesmo ponto no espaço sempre gera a mesma altura, independente de qual chunk é gerado primeiro. Sem gaps ou descontinuidades nas bordas.

→ Arquitetura stateless do compute shader garante isso automaticamente

Peixes 2D (pixel art) em 3D

Billboard rendering: o quad dos peixes sempre aponta para a câmera (via vertex shader com rotation). A textura pixel art é uma spritesheet com frames de animação de natação. School behavior simples com steering separation + alignment.

→ Leve, visual charmoso e consistente com a estética voxel

Save apenas de deltas (chunks modificados)

O mundo procedural é reproduzível a partir do seed. Salvar todo o mapa seria gigantesco. Apenas os chunks com blocos diferentes do gerado são salvos em disco. No load, gera proceduralmente e aplica o delta por cima.

→ Saves compactos, comparáveis aos de Minecraft

Pirita + Água = Ácido Sulfúrico

No bioma de montanhas, blocos de pirita adjacentes à água (chuva ou rios) disparam uma reação: geram ácido sulfúrico (bloco corrosivo) e dióxido de enxofre (partícula de fumaça). Sistema reativo simples com verificação de vizinhos.

→ Implementar na Fase 4 como mecânica de ambiente
